# Проверка ED Copilot 2.3.0

## Среда и команды

Проверки окна и установщика выполняются на Windows 10/11 x64. Нужны Go версии из `go.mod` с указанным toolchain, PowerShell и Microsoft Edge WebView2 Runtime. Игровая логика и расчёты работают на Go, основное окно — во встроенном WebView2, оверлей — через Win32. Локальные HTML, CSS, JavaScript и иконки входят в EXE.

Для контрактных тестов интерфейса нужен Node.js 24. Он используется только при разработке и в CI; пользователю приложения Node.js, Go и Python устанавливать не требуется. Тесты используют встроенный `node:test`, без установки npm-пакетов. Из корня проекта:

```powershell
go mod verify
go test ./... -count=1 -timeout=120s
go vet ./...
go test ./... -count=1 -timeout=120s -coverprofile=coverage.out
go tool cover -func=coverage.out

$frontendTests = @(Get-ChildItem -LiteralPath 'internal/frontend' -Filter '*.test.cjs' -File | Sort-Object Name | ForEach-Object { $_.FullName })
if ($frontendTests.Count -eq 0) { throw 'Frontend tests were not found.' }
node --test @frontendTests
if ($LASTEXITCODE) { throw 'Frontend tests failed.' }

.\build.ps1 -Smoke -Package -Installer
```

Обычный `build.ps1` выполняет Go-тесты, `go vet`, генерацию ресурсов Windows, сборку `dist\ED Copilot.exe` и smoke без окна. `-Smoke` дополнительно проверяет окно WebView2 на изолированных данных. `-Package` создаёт переносимый архив, `-Installer` — установочный EXE. Сочетание `-Smoke -Installer` запускает также изолированную установку, обновление и удаление тестовой копии. Контрактные Node-тесты запускаются отдельно приведённой командой и отдельным шагом `verify` в GitHub Actions.

Параметр `-SkipTests` предназначен для сборки после отдельного полного прогона Go-тестов и `go vet`; сам по себе он не подтверждает их прохождение.

Итоговое число тестов, smoke-сценариев и покрытие берите из отчётов конкретного запуска.

Детектор гонок на Windows требует доступного GCC и `CGO_ENABLED=1`. Команда CI:

```powershell
$env:CGO_ENABLED = '1'
go test -race '-gcflags=github.com/lxn/...=-d=checkptr=0' ./... -count=1 -timeout=180s
```

Race detector включён для всех пакетов. Отдельная проверка `checkptr` отключена только для внешних пакетов `github.com/lxn/walk` и `github.com/lxn/win`: они передают числовой идентификатор ресурса через тип указателя, как предусмотрено [Win32 MAKEINTRESOURCE](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-makeintresourcew). Проверки указателей кода ED Copilot и остальных зависимостей остаются включены. Обычная сборка не использует этот флаг.

## Изоляция данных и демонстрация

Модульные и интеграционные тесты создают синтетические журналы, отдельные временные профили и заранее известные ответы внешних сервисов. Сетевые проверки используют подменяемые HTTP-клиенты или локальные тестовые серверы. Личные журналы, ключи и рабочий профиль игрока для таких тестов не требуются.

Для ручной проверки нового интерфейса без сети и личного профиля:

```powershell
& ".\dist\ED Copilot.exe" --demo
```

`--demo` создаёт временный профиль с синтетическим сеансом и независимыми планами колоний, отключает внешнюю сеть и оставляет окно открытым для ручной проверки. Изменения сохраняются только в этой временной демонстрации. Для завершения используйте меню приложения → «Выход» либо значок в области уведомлений → «Выход».

Обычный запуск использует `%LOCALAPPDATA%\ED Copilot`. Для проверки собственного набора синтетических журналов задайте обе папки явно:

```powershell
& ".\dist\ED Copilot.exe" --data-dir "C:\Copilot-Test\Profile" --journal-dir "C:\Copilot-Test\Journals"
```

Пустая папка журналов покажет ожидание данных. Такой запуск, в отличие от `--demo`, не отключает сеть автоматически. Синтетические записи храните отдельно от журналов командира. Для сценариев с перезапуском используйте одни и те же явно заданные папки: повторный `--demo` создаёт новую демонстрацию и не проверяет восстановление прежнего профиля.

Проверки маршрута используют контролируемые ответы Spansh. Они проверяют обработку топлива, остановок, времени, резерва, ошибочных ответов и условий расчёта. Это не подтверждение доступности реального рынка или фактической длительности очереди прыжка.

Windows-интеграция 2.3 дополнительно проходит состояние интерфейса через мост к настоящему Go-движку на временном профиле: результаты рейсов, назначение рынка, сохранение полного снимка, текущий план плеча и его очистку. Проверка сохранённых котировок сверяет сами системы, станции, даты, цены и условия, а не только наличие записи. Проверка справочных систем сохраняет одновременно содержимое справочника и подлинные синтетические наблюдения журнала, не подмешивая другую систему.

## Smoke без окна

```powershell
New-Item -ItemType Directory -Force .\artifacts | Out-Null
& ".\dist\ED Copilot.exe" --smoke-headless --smoke-report ".\artifacts\smoke-headless.json" | Out-Null
Get-Content .\artifacts\smoke-headless.json
```

Режим сам создаёт временные папки профиля и журналов, записывает синтетический сеанс и планы колоний, отключает сеть и сохраняет JSON-отчёт. Он проверяет запуск модели, чтение синтетических данных, отображаемое название корабля и наличие независимых колоний. Проверьте `ok: true`, `networkDisabled: true` и версию приложения.

В режимах `--smoke`, `--smoke-headless` и `--demo` указанные `--data-dir` и `--journal-dir` заменяются временными папками. Рабочий профиль игрока не используется.

## Smoke окна WebView2

```powershell
& ".\dist\ED Copilot.exe" --smoke --smoke-report ".\artifacts\smoke-native.json" | Out-Null
Get-Content .\artifacts\smoke-native.json
```

Режим открывает основное окно на синтетических данных и проходит разделы, переключатели режимов, доступность действий, поля форм и их отмену. Он дополнительно проверяет каталог и читатель Академии, калькулятор обоих типов носителя, редактор бокового меню, поиск разделов, встроенную верхнюю панель, оформление прокрутки и явное применение палитры. Go проверяет скрытие Win32 HUD при активном окне Copilot. Затем программа сохраняет отчёт и завершается.

Проверяются также полный справочный читатель, каталог кораблей, страница инженера, групповые рецепты, торговля флотоносцем и отдельный экран торговых рейсов. Поиск рынков в smoke использует заранее заданные данные; разрешение на реальные HTTP-запросы этот режим не включает. Тест HTTP-транспорта с постраничным поиском и ошибками выполняется отдельно в Go-наборе, чтобы демонстрационные данные не скрывали ошибки реального пути поиска.

Имя `smoke-native.json` сохранено для совместимости сборки. Поле `renderer` показывает текущую связку WebView2, Go и Win32 HUD. Проверьте `ok: true`, `networkDisabled: true`, `hudHidden: true`, пустой список `problems`, записи `scenarios` и перечень проверенных `forms`.

Рядом с отчётом создаются PNG основных экранов, читателя и форм, в том числе `modern-overview.png`, `modern-academy.png`, `modern-reader.png`, `modern-calculator.png`, `modern-calculator-squadron.png`, `modern-colonization.png` и `modern-settings.png`. Их снимает непосредственно WebView2 CapturePreview, поэтому результат не зависит от захвата рабочего стола. Повреждённый, отсутствующий или одноцветный обязательный снимок завершает smoke с ошибкой. В отчёте `screenshots` указаны фактический состав, размеры и число найденных цветов, а `webviewGeometry.ok` подтверждает видимость, ненулевой размер и размещение WebView внутри клиентской панели окна. Просмотрите читаемость русского текста, изображения сущностей, границы панелей, боковое меню, встроенную верхнюю панель, контраст и отсутствие перекрытий. Дополнительно smoke сохраняет заполненную таблицу строительства, длинную форму и «Обзор» в окне 900 × 700. Снимки дополняют ручную проверку навигации и оконных действий. В `interactionTimings` сохранены времена проверенных действий; это измерения конкретного запуска, а не универсальное обещание задержки.

### Изображения для README

Снимки README получают только из изолированного **`--smoke`**. Галерея в `docs/screenshots/` включает `overview.png`, `deals.png`, `carrier-trade.png`, `route.png`, `ships.png`, `ship.png`, `engineer.png`, `article.png`, `colonization.png` и `academy.png`. Кадры с префиксом `modern-readme-` из отчёта smoke соответствуют именам без этого префикса в документации. Для релиза обновляйте галерею одной версией приложения и проверяйте размер каждого кадра 1920 × 1080.

Перед копированием проверьте, что нет сообщений об ошибке, незавершённой загрузки, перекрывающих уведомлений и дублирующего плейсхолдера рядом с реальным изображением. Подпись README должна явно обозначать демонстрационные данные. Рабочий профиль, настоящие журналы и снимки подключённого аккаунта для этой галереи не используются.

Если `--smoke-report` не указан, отчёт сохраняется внутри созданной временной папки. Для воспроизводимой проверки всегда задавайте путь.

## Smoke установщика

```powershell
.\build.ps1 -Smoke -Package -Installer
Get-Content .\dist\smoke-installer.json
Get-Content .\dist\SHA256SUMS.txt
```

Сборка проверяет и подготавливает Inno Setup и официальный bootstrapper Microsoft WebView2. Подробности установки компонентов описаны в [инструкции установки](INSTALLATION.md).

Проверка установщика использует отдельный идентификатор приложения, каталог внутри `dist`, синтетический профиль и тестовые ярлыки внутри изолированной папки. Проверяются отказ автоматической установки при отсутствующем Runtime, блокировка замены работающего приложения по mutex, выбранная папка, регистрация удаления для текущего пользователя, необязательный ярлык рабочего стола, запуск установленного EXE, обновление и удаление. Пользовательские файлы и профиль должны сохраниться. Контрольные суммы рабочего профиля сравниваются до и после проверки без использования его содержимого в приложении.

В `smoke-installer.json` проверьте `ok: true`, `isolated: true`, `profileUnchanged: true`, `windowsComponentsInstalled: false` и результаты всех `scenarios`. Установочный smoke сам не устанавливает WebView2. В одноразовой среде GitHub Actions Runtime предварительно готовит отдельный CI-скрипт; на рабочем компьютере он запускаться не должен.

## Ручной smoke

Сначала выполните действия в `--demo`, затем отдельно проверьте интеграции в своём игровом сеансе.

1. Проверьте обзор: система, модель корабля, личное имя, идентификатор, груз и переключение экранов. Выбранная строка должна обновлять правую панель подробностей и значения действий.
2. Через **…** рядом с названием приложения откройте настройку бокового меню. Добавьте и скройте необязательный раздел, перетащите его на новое место, сверните меню и найдите раздел через **Ctrl+K**. После полного выхода проверьте сохранение порядка в том же тестовом профиле.
3. Проверьте встроенную верхнюю панель: перетаскивание окна, сворачивание, разворачивание и возврат размера. В настройках переключите окно, полный экран и окно без рамки. Проверьте прокрутку, узкое окно и масштаб Windows; текст, поля и кнопки должны оставаться доступны.
4. Переключите режимы над таблицей, выберите вторую строку, откройте основное действие и **«Ещё»**. Проверьте исходные значения формы, отмену и отсутствие сообщения о сохранении при отмене. Для длинной формы проверьте прокрутку и клавиатурный фокус.
5. Откройте Академию: категории, русский поиск, избранное и продолжение чтения. Прочитайте основы, практикум и самопроверку одного курса. Проверьте оглавление, режим чтения и Escape, чек-лист, раскрытие разбора, изменение ответа, ручную отметку «Изучено», переходы между уроками и открытие рабочего инструмента. После полного выхода вернитесь к сохранённой позиции.
6. В калькуляторе задайте разные параметры для личного и эскадрильного носителей. Проверьте службы и их приостановку, обязательные службы, бюджет и резерв, сравнение типов, сохранение каждого плана. Пустые необязательные цены должны отображаться как неизвестные, неверные числа — отклоняться до отправки. Проверьте, что сброс одного плана сохраняет второй.
7. Для двух колоний задайте разные объекты, сметы, вместимость и очереди снабжения. Измените одну, переключитесь на другую и проверьте независимость. Выбранная колония должна совпадать с задачами её HUD и экспортом.
8. Проверьте предпросмотр и применение палитры, импорт цветов из игры, кириллицу, инженерный список и поиск по энциклопедии. Отмена предпросмотра не должна менять сохранённую тему. Раздел помощи должен соответствовать открытому инструменту.
9. В игровом сеансе включите HUD и выберите разные занятия. Проверьте скрытие в ED Copilot и другом приложении, показ только при активной игре, положение в корабле, ТРП/Nomad и пешком. Выключение должно скрывать также выбор занятия.
10. Найдите рынки покупки и продажи: проверьте цену, спрос либо запас, дату, расстояние и выбранное назначение. Сопоставьте сделку с журналом игры. Рассчитайте маршрут флотоносца, сверьте топливо и остановки с ответом провайдера, а время — со своими введёнными длительностями. После изменения загрузки пересчитайте маршрут.
11. Проверьте установку и обновление в отдельную папку: ярлыки, версию и запуск. Завершите приложение полностью, удалите тестовую установку и убедитесь в сохранности профиля и добавленного вручную файла. Для проверки регистрации установщика используйте изолированный автоматический smoke, если рабочая версия должна остаться установленной.

Для новых экранов 2.2 дополнительно пройдите следующие действия:

1. Откройте категории энциклопедии и «Всё», измените запрос и группу, перейдите на следующую страницу. Быстро замените запрос: старый ответ не должен возвращать прежние результаты. Проверьте очистку пустого поиска.
2. Откройте корабль, инженера из энциклопедии и экранов «Инженеры», статью, материал, чертёж и эффект. Проверьте полную ширину страницы, изображение без дополнительного значка-плейсхолдера, оглавление, рецепты уровней, переход к связанной сущности и возврат к прежнему списку.
3. На странице товара проверьте покупку и продажу, запрос рынков, цену, запас или спрос, дальность и время. После поиска другого товара прежние предложения не должны смешиваться. «Все фильтры в торговле» должны сохранить выбранный товар и операцию. Реальный онлайн-поиск проверяется отдельным разрешённым сеансом.
4. В торговле флотоносцем заполните оба плеча и сохраните план. Проверьте пустой возврат, вознаграждение перевозчиков, изменение свободного объёма от трития, импорт маршрута в нужное плечо, расходы, прибыль, рентабельность и окупаемость. Неизвестные цены должны оставлять зависимые итоги неизвестными.
5. Выберите Booze Cruise: цена вина должна требовать ввода либо подтверждённой котировки. Проверьте несовместимость большого перевозчика с Rackham’s Peak и отдельное подтверждение Public Holiday.
6. На маршруте включите копирование следующей системы. На синтетических событиях проверьте прибытие своего флотоносца, одноразовую команду следующей остановки, отсутствие команды от повторного события и старого журнала, затем выключение флажка. Назначение прыжка в игре не должно выполняться приложением.

Вход Frontier, отправка в Inara и ответы действующих внешних сервисов проверяются отдельно при наличии подходящего аккаунта и разрешения владельца. Успех тестов с подменённой сетью не заявляется как проверка этих сервисов в реальном сеансе.

Автоматический smoke не заменяет визуальную проверку всех масштабов Windows, конфигураций мониторов и игровых ситуаций. Результаты проверки с детектором гонок или настоящими внешними серверами следует указывать только при наличии соответствующего отчёта.


## Нагрузочная проверка

`build.ps1 -Smoke` дополнительно создаёт `smoke-stress.json` на 300 системах и 3000 телах. Обычный и нагрузочный smoke проверяют обработчики оконных кнопок, F11 и переходов; время находится в `interactionTimings`. Подробности и команда `--demo --stress` приведены в [описании производительности](PERFORMANCE.md).
